# 0.0.0 — the language probes — PLANNED

> **Scope:** nine programs asking the compiler whether this repository's shape
> is spellable. No utility is written. What this produces is a **verdict per
> probe**, and where a verdict is negative, an amended specification and a
> recorded decision.
>
> **Probe 02 gates the repository, not the cycle.** PX-010 makes `failsafe` a
> macro because sixty hand-written exhaustive `pick`s is twelve hundred lines
> that must stay in sync — and nothing in the compiler's own tree demonstrates
> a macro splicing a `pick` into a function body. Run it first.

## 1. Where you are

- Nothing is built. `src/posix/` and `src/util/` hold placeholders.
- The compiler is at `../../../nitpick`, cycle 1.5. Build it per its own
  `CLAUDE.md`; the artifact these probes use is `build/npkc`.
- There is no harness yet — probes are run by hand, one command each, and that
  is deliberate: building a harness against unverified assumptions about
  `failsafe` is the mistake this subcycle exists to avoid.
- The probes stay in the tree permanently as `tests/probe/`, and 0.0.2 picks
  them up as ordinary `unit`-stage entries.

## 2. The command

```
$NPKC tests/probe/NN_name.npk -o /tmp/p.ll \
  && llc -O0 -filetype=obj -relocation-model=static /tmp/p.ll -o /tmp/p.o \
  && ld.lld -static /tmp/p.o ../../../nitpick/build/npkrt.o -o /tmp/p \
  && /tmp/p ; echo "exit $?"
```

Each probe exits 0 on success and a distinct positive code per failed
assertion. `exit 0` additionally asserts, through D-151 and D-188, that nothing
leaked.

## 3. Decisions taken at planning

- **P-1 — probe 02 runs first and alone.** Its answer decides whether the other
  eight are worth writing in their current form.
- **P-2 — a refused probe is a result, not a failure of the subcycle.** Probe
  05 (`SIGPIPE`) and probe 06's first half are *expected* to die; their value
  is that they die the documented way.
- **P-3 — the fallback for probe 02 is written down now**, before it is
  needed: a generated `failsafe` per utility, emitted by the harness from the
  reachable-error set and committed. It is worse in every way except certainty
  — a generated file per utility is a generated file per utility — and writing
  it down now is what stops it being improvised under pressure at the moment
  the plan is already wrong.
- **P-4 — a negative verdict amends the specification in the same commit.**

## 4. The probes

### 02 — `failsafe` as a macro expansion **(run first)**
**Asks:** can `#posix_failsafe(e)` expand, in statement position inside
`func:failsafe`, to an exhaustive `pick` that satisfies REACH-002?

```nitpick
macro:posix_failsafe = (E) {
    pick (E) {
        (HeapOom)          { exit 70i32; },
        (HeapBadRequest)   { exit 70i32; },
        (WildLeak)         { exit 70i32; },
        (IntOverflow)      { exit 70i32; },
        (OutOfBounds)      { exit 70i32; },
        (Unreachable)      { exit 70i32; },
        (DivByZero)        { exit 70i32; },
        (DivOverflow)      { exit 70i32; },
        (DeadlineExceeded) { exit 70i32; },
        (*)                { exit 70i32; }
    }
    exit 70i32;
};

func:failsafe = int32(Error:e) { #posix_failsafe(e) };
```

**Matters because** PX-010 rests entirely on it, and `MACRO_REFERENCE.md`
specifies expansion in four positions and splicing into structs and impls
without demonstrating this shape.

**A negative verdict** takes P-3's fallback and replans 0.1.

**Read `MACRO_REFERENCE.md` in full before writing this**, including the
hygiene rules — the macro names `Error`'s variants, which are prelude names,
and D-124's hygiene is exactly what governs whether that resolves.

### 02b — the extended form
`#posix_failsafe_with(e, EOne, ETwo)` — the shared arms plus named extras
(S-4). Two user errors declared in the probe, both named, both reached.

### 01 — `argv`
`cstring[]:argv` read; an operand converted to an owned `string`; the borrow
edges exercised — passing a view down (legal), returning one (refused), holding
one in a struct that outlives the call (refused). `argv` is the kernel's memory
and outlives the program, which is why `Args` may hold views into it (G-13),
and this probe is what establishes that rather than assuming it.

### 03 — one module, two artifacts
A shared module compiled into two separate programs, each linked statically,
each passing the undefined-symbol scan. **Matters because** B-3 says the shared
runtime is compiled per utility rather than linked once, and sixty artifacts
each carrying it is PX-014's whole question.

### 04 — exit status
`exit` from `main` and from `failsafe`; the status observed by a parent through
`lib/nproc.npk`'s `proc_wait`. Asserts S-12's convention is expressible.

### 05 — `SIGPIPE` **(expected to die)**
Write to a pipe whose reader has exited. **The process must terminate with
signal 13**, and the parent must observe it. This is the inverse of `ntui`'s
T-113 test and it is the evidence for PX-011 — that the default disposition is
live, and that a POSIX utility wants it that way.

### 06 — the accumulator **(two programs)**
`acc = acc * 10 + d` over a 25-digit string, **expected to trap** with
`IntOverflow`; and the same input through a checked helper, expected to exit 0
with a reported range error. Day one produces evidence for `SAFETY.md` S-9
rather than a claim.

### 07 — `openat` and `O_NOFOLLOW`
A directory descriptor kept across a walk, a child opened relative to it, and a
symlink refused. **Matters because** F-3 makes descriptor-relative traversal the
rule for six utilities and `lib/nfs.npk` is the working precedent.

### 08 — `getdents64`
A directory read, including a filename containing invalid UTF-8, surviving
unchanged through a read and a write. **Matters because** F-4 says a path is
bytes, not text, and a utility that mangles such a name is a utility that
renames the wrong file.

### 09 — standard input once
`-` as an operand twice: opened once, exhausted the second time (G-19). Small,
and it pins a rule that is easy to get wrong in the shared runtime.

## 7. What the executor should know

- **Reserved words**: `test`, `true` and `false` are fine as *directory* names
  and as module names; `in`, `end`, `limit`, `any`, `buffer`, `raw`, `move`,
  `error`, `fd` and `on` are not available as locals. The full table is
  `../../../../nitpick-libs/PLAYBOOK.md` §10.
- **`discard(x);` takes parentheses; `defer { … }` takes no trailing
  semicolon.** Declarations end `};`; control-flow blocks do not.
- **A file's `mod:` name must equal its basename.**
- **`raw` is licensed only on a `never fails` callee** (D-163), and an `async`
  callee never is.
- **Exit 0 means "and nothing leaked"** (D-151, D-188).
- **The prelude's error identities are what probe 02's macro names.** Copy the
  arm set from `../../../nitpick/tests/backend/programs/proc_tool.npk` and
  prune to what a utility can actually reach.
